Why volley

Fast, observable, secure by default

Built for production load: the generator is fast, the metrics are trustworthy, and secrets never sit in a scenario file.

Lock-free core

Async I/O on Boost.Beast/ASIO with lock-free metrics and connection pooling — the generator does not become the bottleneck.

Three protocols

HTTP/1.1, WebSocket and raw TCP, plus custom protocols via a factory pattern — one tool for mixed workloads.

Full observability

OTLP/HTTP+JSON tracing, a Prometheus /metrics endpoint and SLA validation — results are measured, not eyeballed.

Secrets handled

OAuth2, HashiCorp Vault, mTLS and API keys out of the box — credentials stay out of YAML scenarios.

YAML scenarios

Load profiles are declarative YAML: reviewable, versionable and diff-able like any other config.

Hardened CI

An 8-job pipeline with ASan/TSan, 100% test coverage and zero warnings — the tool is tested as hard as the targets.

Build

From source in four commands

CMake + Ninja, Release build, then ctest. Dependencies are standard system packages.

C++20 Boost.Beast ASIO yaml-cpp OpenTelemetry Prometheus CMake
terminal
$ cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
$ cmake --build build
$ cd build && ctest --output-on-failure
